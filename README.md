# Telegram Campaign Bot

Панель управления (обычный Bot API бот) + два юзер-аккаунта на Telethon:

- **аккаунт мониторинга** - работает **24/7**: как только процесс стартует,
  мониторинг сам запускается в фоне и слушает **только новые сообщения**
  (никакой истории) в добавленных группах. Он сам ждёт, пока вы войдёте в
  аккаунт, сам подхватывает новые группы, и сам переподключается при любых
  обрывах связи - вручную "запускать" его не нужно, нужно только один раз
  войти (кнопка в меню).
- **аккаунт рассылки** - шлёт сообщение (с форматированием и премиум-эмодзи)
  всей базе рассылки. Запускается **только вручную**, по нажатию кнопки, и
  идёт до конца списка без остановки на отдельных ошибках. Вход в этот
  аккаунт бот запрашивает **строго в момент**, когда вы жмёте «Разослать с
  личного аккаунта» и аккаунт ещё не авторизован - отдельной кнопки «войти»
  для него нет.

Автор каждого нового сообщения в отслеживаемых группах проверяется по базе
рассылки: если его там ещё нет - добавляется, если уже есть (по id или
username) - пропускается, дублей не будет.

## Структура проекта

```
settings.py           - ЕДИНСТВЕННЫЙ файл с настройками (секреты из .env + все
                         "магические числа": пути, задержки, spam-bot, порт и т.д.)
storage.py             - JSON-хранилище + база рассылки с защитой от дублей
states.py               - состояния диалога бота (aiogram FSM)
userbot_manager.py       - логика входа Telethon-клиента (код, 2FA, сброс сессии)
groups.py                 - разбор ввода групп (ссылка/ссылка на сообщение/id/юзернейм)
monitor.py                - мониторинг новых сообщений 24/7, авто-переподключение
broadcast.py                - рассылка: скип ошибок, авто-снятие спам-блока
main.py                       - Bot API бот: меню, сброс данных, keep-alive сервер
render.yaml                    - Render Blueprint (web-сервис + cron keep-alive)
```

**Менять код обычно не нужно** - все настройки в `settings.py` (секреты
берутся из `.env` / Render Environment, остальное можно поправить прямо в
файле).

## Как это работает

### Мониторинг (24/7)

При старте процесса (`main.py`) сразу запускается фоновый цикл мониторинга.
Он:
- если аккаунт мониторинга ещё не авторизован - просто ждёт (проверяет
  каждые `MONITOR_RETRY_SECONDS`, по умолчанию 30 сек);
- если список групп пуст - тоже ждёт;
- слушает событие «новое сообщение» (`events.NewMessage`) - оно по своей
  природе ловит только то, что приходит уже после подключения, историю
  чата бот не перечитывает;
- при обрыве связи (сеть, рестарт Telegram-сессии и т.п.) - сам
  переподключается и продолжает работать, никаких действий от вас не
  требуется;
- при добавлении новой группы или после входа в аккаунт - переподключается
  немедленно (не ждёт случайного обрыва), чтобы подхватить изменения сразу.

Кнопка «🔑 Войти: аккаунт мониторинга» в меню нужна только один раз - чтобы
дать боту войти в аккаунт. Дальше он работает сам.

### Добавление групп

При нажатии «➕ Добавить группу» можно прислать несколько строк за раз, в
любом из форматов:

- **ссылка на конкретное сообщение (рекомендуется)** - откройте в Telegram
  любое сообщение в нужной группе → «Копировать ссылку». Для обычной
  группы получится вида `https://t.me/mygroup/123`, для приватной группы
  без публичного username - `https://t.me/c/1234567890/123`. Это самый
  надёжный способ: не нужна ни ссылка-приглашение, ни username, а группа
  однозначно определяется даже без прав приглашать;
- обычная ссылка на группу: `https://t.me/mygroup`;
- `@username` группы;
- числовой id группы/канала: `-1001234567890`.

Если аккаунт мониторинга уже авторизован, бот сразу проверяет доступ к
каждой группе и прямо сообщает, что не получилось добавить (например,
если аккаунт в неё не входит) - вместо того чтобы молча копить нерабочие
записи. Дубли (по фактическому чату, а не по тексту ссылки) отфильтровываются
автоматически.

### Рассылка (вручную, до конца списка)

Запускается только по нажатию кнопки «📤 Разослать с личного акк.» - никакого
автозапуска. Пока рассылка не закончилась, повторно запустить её нельзя
(бот сообщит, что рассылка уже идёт).

Рассылка идёт по всей базе до конца, ошибки на отдельных получателях
**пропускаются** и не останавливают процесс. Если сообщение не удалось
отправить:
1. Аккаунт рассылки сам отправляет `/start` официальному `@SpamBot`, чтобы
   попытаться снять возможное ограничение (на аккаунтах с Telegram Premium
   это часто снимает блок сразу же).
2. Ждёт `SPAMBLOCK_RETRY_DELAY_SECONDS` (по умолчанию 3 сек) и повторяет
   отправку один раз.
3. Если и это не помогло - получатель попадает в список ошибок в итоговом
   отчёте (для истории/отладки), **но всё равно засчитывается как
   получивший сообщение** - так одна проблемная запись не блокирует
   прогресс и не вызывает бесконечные повторные попытки в будущих
   рассылках. Это поведение можно отключить, поставив в `.env`
   `ENABLE_SPAMBOT_RECOVERY=false` (тогда `/start` спам-боту слаться не будет).

### Прочее

- **Сообщение рассылки** - присылаете боту сообщение ровно так, как оно
  должно выглядеть у получателей (форматирование и премиум-эмодзи Telegram
  передаёт как "entities", бот их сохраняет 1-в-1).
- **Получатели вручную** - можно дополнительно добавить @username/id в базу
  рассылки руками, дубли отфильтровываются так же, как и при автосборе.
- **Рассылка от бота** - есть настоящие inline-кнопки, но получатель должен
  был хотя бы раз написать боту `/start`. Отдельного логина не требует.
- **📊 Статус** в меню - сколько групп, сколько в базе рассылки, авторизованы
  ли аккаунты, запущен ли мониторинг, идёт ли сейчас рассылка.
- **🧹 Сбросить данные** в меню - можно сбросить (с подтверждением):
  сессию аккаунта мониторинга, сессию аккаунта рассылки, список групп, базу
  рассылки, сообщение рассылки. Сброс сессии реально разлогинивает аккаунт
  в Telegram (`client.log_out()`) и чистит файлы сессии на диске - после
  этого понадобится полный повторный вход.

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env
# впишите API_ID / API_HASH (my.telegram.org), BOT_TOKEN (@BotFather), ADMIN_IDS
python main.py
```

Напишите своему боту `/start` - откроется меню.

## Деплой на Render (через GitHub)

1. Запушьте проект в свой репозиторий на GitHub (`.env`, `storage/` и т.п.
   игнорируются `.gitignore` - секреты и сессии в git не попадут).
2. В Render: **New → Blueprint**, выберите репозиторий - Render найдёт
   `render.yaml` и предложит создать:
   - `tg-campaign-bot` - web-сервис (нужен для health-check и keep-alive
     пинга) с примонтированным **Persistent Disk** в `/var/data` (там
     хранятся сессии Telethon и база рассылки - без диска они бы стирались
     при каждом передеплое/рестарте);
   - `tg-campaign-bot-keepalive` - Render Cron Job, пингует сервис каждые
     10 минут, чтобы он не "засыпал".
3. Заполните секретные переменные окружения у сервиса `tg-campaign-bot`
   (`API_ID`, `API_HASH`, `BOT_TOKEN`, `ADMIN_IDS`) в Render Dashboard →
   сервис → **Environment**.
4. После первого деплоя скопируйте публичный URL сервиса `tg-campaign-bot`
   (вида `https://tg-campaign-bot-xxxx.onrender.com`, без слеша на конце) и
   впишите его в переменную `APP_URL` у джобы `tg-campaign-bot-keepalive`.
5. Готово. Дальше при каждом `git push` в `main` Render сам пересоберёт и
   передеплоит бота (`autoDeploy: true`), а cron каждые 10 минут будет
   держать сервис "живым".

### ⚠️ Важный компромисс: план Render vs "не засыпать"

- Диск (`disk:` в `render.yaml`), а значит и сохранность сессий/базы
  рассылки между рестартами - доступен **только на платных планах**
  (в файле указан `starter`). На платном плане сервис и без пинга **не
  засыпает** сам по себе - cron-пинг тут просто подстраховка, лишним не
  будет.
- Если вы поставите `plan: free`, чтобы не платить - у Render **нет
  персистентного диска на бесплатном плане**, а значит сессии Telethon и
  база рассылки будут теряться при каждом рестарте/передеплое, и придётся
  заново логиниться в оба аккаунта. Пинг раз в 10 минут на free-плане
  действительно не даст сервису заснуть от бездействия, но проблему с
  потерей данных не решает.
- Рекомендация: используйте платный план (`starter` и выше) - тогда и
  данные сохраняются, и сон не грозит в принципе.

## Важно понимать перед использованием

- **Автоматизация личного аккаунта через API (вход по коду/2FA, скрипты,
  а тем более авто-отправка `/start` спам-боту) - формально нарушение
  пользовательского соглашения Telegram.** При активном использовании
  (особенно частые рассылки) аккаунт может получить ограничения или
  блокировку. Используйте на свой риск и по возможности - на аккаунте, не
  критичном для вас.
- Делайте паузы между сообщениями при рассылке (по умолчанию
  `BROADCAST_DELAY_SECONDS = 2.5` в `settings.py`) - резкая массовая
  отправка почти гарантированно ловит анти-спам лимиты.
- Собирайте и используйте данные участников групп только с пониманием,
  что это живые люди - не рассылайте им то, на что они не подписывались.
- Файлы сессий (`storage/sessions/*.session`) дают полный доступ к
  аккаунту - храните их так же аккуратно, как пароль, и никогда не
  коммитьте в git (см. `.gitignore`).
